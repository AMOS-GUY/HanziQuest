# M16.2: Audio foundation (research and proposal)

Status: **research only, plus a provider-independent player.** No audio is recorded, bought,
scraped, generated or shipped. No provider is chosen. Every option below needs an owner decision.
Written 2026-11-27.

Costs, licence terms and browser-support details marked _(unverified)_ come from general
knowledge, not from a check done for this document. Confirm them against the provider's current
terms before relying on them.

## Where things stand

- **Data.** `Vocabulary.audioUrl` exists, a nullable string. `Character` has no audio field.
  All 81 HSK 1 Starter words have `audioUrl = null`. Content files can't set it: the format has
  no audio field.
- **Playback.**
  - The word page (`/vocabulary/[id]`) already renders `<audio controls>` when `audioUrl` is
    set.
  - M16.1 adds `WordAudio` (`src/components/vocabulary/word-audio.tsx`). It renders nothing when
    there's no recording, so there's no fake button and no placeholder sound. Otherwise it renders
    a labelled native player with `preload="none"`. It doesn't know or care where the file comes
    from.
- **Review.** `audioUrl` is part of the content-review fingerprint
  (`review-fingerprint.ts`). Changing it invalidates an approval. The fingerprint covers the URL
  string, not the audio bytes: see "Content addressing" below.
- **CSP.** `media-src 'self' blob:` and `connect-src 'self'` (`next.config.ts`). Same-origin audio
  works today. Audio from any other origin is blocked until the CSP changes.
- **Offline.** The service worker (`public/sw.js`, `hq-sw-1`) has no rule for audio. Audio
  requests go to the network and aren't cached.

## Requirements

1. Every recording has a recorded source and licence that allow HanziQuest's use, including
   offline copies on learners' devices.
2. The pronunciation is standard Mandarin (Putonghua), checked by the same qualified reviewer
   flow as other content (D-075). A recording is learner-visible content.
3. The audio matches the displayed pinyin, including the tone-marking policy (see the content
   audit in `M16-vocabulary-explorer.md`: 不 sandhi, 你好 citation tones, neutral tones).
4. Changing a recording invalidates its review approval.
5. No provider lock-in: the app plays a same-origin file, whoever produced it.
6. It works without audio. Audio is an enhancement, never required to progress.

## Proposed data model (not implemented)

Use the expand, then contract pattern (CLAUDE.md, `db:check-migrations`) and keep the FK graph
acyclic.

```text
AudioAsset
  id            cuid
  sha256        unique: content hash of the file bytes
  path          same-origin path, content-addressed: /audio/<sha256>.<ext>
  mimeType      audio/mpeg | audio/mp4 | audio/ogg
  durationMs    int
  bytes         int
  sourceRefs    string[]: ids from content/sources.json (M14)
  licenseStatus existing enum
  attribution   string?: required when the licence requires it
  speakerCode   string?: an opaque code, never a name or contact detail
  synthetic     boolean: true for TTS
  createdAt

VocabularyAudio (vocabularyId, audioAssetId, role WORD | SLOW, position)
```

- **Expand.** Add the tables and keep `Vocabulary.audioUrl`. The importer sets `audioUrl` from
  the WORD asset's path, so existing pages and `WordAudio` keep working unchanged.
- **Contract,** later and optionally: read through the join and drop `audioUrl` once nothing reads
  it.
- **Characters** get the same join (`CharacterAudio`) only if single-character audio is wanted.
  Word audio covers single-character words already.
- **Content files** gain an optional `audio` entry per word: `{ file, sourceRef, license,
attribution?, synthetic }`. The importer hashes the file, so curriculum structure doesn't
  change.

## Content addressing (required)

The review fingerprint hashes `audioUrl`, not the file. If a file at the same URL were replaced,
the approval would silently cover different audio. Paths must therefore contain the file's
SHA-256 (`/audio/<sha256>.mp3`). That way a different recording means a different URL, which
means a different fingerprint and a new review. Alternatively, add the hash to the fingerprint,
as `v3`, with a decision entry (D-076 rules). Either is fine. The path approach also makes
caching trivial (immutable).

## Formats

- **Primary format:** MP3 or AAC-LC in `.m4a`. Both play in all current browsers, including
  Safari on iOS _(unverified for the oldest supported versions)_.
- **Opus** (`.ogg` or `.webm`) is smaller at equal quality, but older Safari versions had gaps
  _(unverified)_. If it's used, offer it as a `<source>` alongside an MP3 or AAC fallback.
- **Encoding:**
  - Mono, about 48 to 64 kbps, 44.1 or 48 kHz.
  - Trim silence to about 100 to 150 ms at each end.
  - Normalise loudness across files, so the volume doesn't jump between words. The target level
    needs choosing.
- **Size:** a one-second word clip at 64 kbps is about 8 KB, so all of HSK 1 is under 1 MB.

## Delivery and CSP

- **Same origin (recommended):** `public/audio/` or a same-origin route. No CSP change is needed.
  Immutable cache headers, safe because the paths are content-addressed.
- **Object storage or a CDN on another origin:** add that exact origin to `media-src`. Add it to
  `connect-src` too, if the service worker pre-fetches the files. This is a security-header change,
  so it needs review. Never use wildcards.
- **Range requests:** browsers request byte ranges for media. Next.js static files support them.
  Verify this for any custom route.

## Offline

Today audio isn't cached. To play audio offline:

- **Rule.** Add a service-worker rule for `/audio/` that's cache-first, safe because the files
  are immutable.
- **Cache.** Use a separate `hq-sw-N-audio` cache, and bump `VERSION` (CLAUDE.md).
- **Prefetch.** Optionally prefetch a lesson's audio when the lesson starts, not the whole
  catalogue.
- **Shared devices.** Audio isn't personal data, so a shared cache is acceptable, unlike pages.
  Still, don't prefetch locked lessons' audio, so the cache can't reveal them.
- **Storage.** Respect quota errors, and fall back to the network.
- **Tests.** Test with `npm run build` and Playwright offline flows.

## Player behaviour (now and later)

- **Now (`WordAudio`).**
  - It renders nothing without a source.
  - The native `<audio controls>` is keyboard accessible, labelled "Pronunciation of {word}", and
    has `preload="none"`.
- **Later, if wanted:**
  - A compact play button instead of the native bar.
  - It must keep an accessible name, `aria-pressed` or a live status for playing, and visible
    focus.
  - No autoplay, which also respects `prefers-reduced-motion` for any animation.
  - An error state if the file fails ("Recording unavailable"), never a silent failure.
- **Exercises.** Listening exercises would be new exercise types. That's curriculum data plus an
  importer change, and out of scope here. No fake exercises.

## Open decisions for the owner

1. Choose the source (option A recommended) and approve a recording release form.
2. Approve any spending (speaker fees or TTS). None was spent.
3. Choose same-origin hosting (recommended) or a CDN, with the CSP change that implies.
4. Choose content-addressed paths (recommended) or fingerprint `v3`.
5. Decide whether synthetic audio is acceptable at all, and if so how it's labelled.
6. Approve offline audio caching.
