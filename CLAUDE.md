# CLAUDE.md

Guidance for AI agents working in this repository.

## Project

HanziQuest is a Chinese character handwriting and learning PWA. It is a modular monolith on
Next.js 16 App Router + Prisma 7 + PostgreSQL. The product requirements are the owner's master
prompt. Status and the milestone checklist are in `docs/PROGRESS.md`. Record significant
decisions in `docs/DECISIONS.md`.

## Commands

```bash
npm run db:local            # local Postgres on :5433 (background it; needed for dev/tests)
npm run dev
npm run lint && npm run typecheck && npm test
npm run test:integration    # needs db:local running
npm run build && npx playwright test
npm run content:validate
```

## Rules

- **Logos:** never modify anything in `icon design/`. The app uses copies made by
  `npm run brand:icons`. See `docs/BRANDING.md`.
- **Business rules go in `src/features/*` services** that take a `PrismaClient`. Pages, actions
  and route handlers only validate, authorize and delegate.
- **Authorization is server-side.** Pages call `requirePagePermission`. Server actions and route
  handlers call `assertPermission`. Never rely on hidden UI.
- **Never trust client values** for XP, mastery, roles or entitlements.
- **Curriculum is data.** Never hardcode lessons or exercises in the frontend. Change
  `content/*.json` and re-import.
- **Don't label content official/verified** unless its `verification` is `VERIFIED`.
- **Migrations:** create them with `prisma migrate dev`. Never edit applied migrations. Never run
  `migrate reset` or `db push` against shared or production databases.
- Every protected mutation writes an audit log entry in the same transaction.
- Chinese text: add `lang="zh"` or the `.hanzi` class so the CJK font stack applies.
- Respect `prefers-reduced-motion`. Keep components accessible (labels, focus, contrast).
- Report status honestly. Don't mark features done that are only UI.

## Gotchas

- The Prisma client is generated into `src/generated/prisma` (git-ignored). `npm install` runs
  `prisma generate`.
- Prisma 7 `migrate dev` does **not** regenerate the client. Run `npx prisma generate`, and restart
  `npm run dev`, because the dev server caches the old client on `globalThis`.
- Playwright starts its own `next start` on :3100 with `AUTH_URL` pointed at it. Run
  `npm run build` first.
- Handwriting: thresholds live in `src/features/handwriting/evaluate.ts`. Changing them means
  bumping `ENGINE_VERSION` and re-running `tests/unit/handwriting-engine.test.ts`.
- The local Postgres cluster must be UTF-8 (`scripts/local-postgres.ts` handles it).
- Next 16: `params`/`searchParams` are Promises, and middleware is called `proxy.ts`.
- `hanzi-writer-data` coordinates use a 1024 grid with the y axis pointing up (top edge y = 900).
- Progress effects (XP, mastery, streaks) run inside the attempt transaction under a per-learner
  advisory lock (`features/progress/record.ts`). Mastery/SRS are replayed from
  `AttemptCharacterResult`; never update `CharacterMastery` or `ReviewSchedule` directly.
- Rate limiters are async (`await limiter.consume(key)`); production uses the PostgreSQL store.
- Route handlers must read bodies with `readJson(request, maxBytes)` and be wrapped in
  `handleApi` (origin check, error mapping).
- Admin forms: use `AdminForm` (submits via a transition so input survives validation errors).
- Curriculum edits go through `features/administration/curriculum-admin.ts`; lesson content is
  regenerated by `buildLessonContent` in the importer, never by hand.
- Handwriting thresholds change only with real-sample evidence (`docs/HANDWRITING_VALIDATION.md`).
  Recall vs technique policy lives in `features/handwriting/technique.ts`; don't mix them.
- Handwriting samples from automated tests must use participant codes starting with `TEST`.
- Changing the privacy notice or terms materially: bump `LEGAL_VERSION`.
- Learner-facing lesson queries use `LEARNER_VISIBLE_LESSON` (`features/curriculum/visibility.ts`):
  both the lesson and its curriculum must be PUBLISHED.
- Imports never overwrite reviewed/verified shared characters or words with less verified data
  (`features/curriculum/provenance.ts`). Preview first: `npm run content:preview`.
- Migrations: expand, then contract. `npm run db:check-migrations` must pass. Keep the FK graph
  acyclic (the backup/restore tools depend on it).
- Registration is invite-only in production (`REGISTRATION_MODE`). Playwright starts two
  servers: :3100 (open) and :3101 (invite-only).
- Review queries use `LEARNER_REVIEWABLE_CHARACTER`. Placement checks (tested-out characters
  never written) come from `getPlacementChecks`; they never write schedules (D-044).
- Password reset links are staff-issued (D-045, `features/account/password-reset.ts`); only token
  hashes are stored. Policy is re-checked at use (`usableNow`), and `PASSWORD_RESET_LINKS` is off
  in production until the owner approves (D-047). Playwright's :3100 server turns it on.
- ESLint forbids `dangerouslySetInnerHTML`, `innerHTML` and created scripts: the CSP relies on
  it (D-046).
- Health: `/api/health/live` is liveness (no DB, Docker HEALTHCHECK); `/api/health` is readiness
  (503 while a shipped migration is unapplied). Logic in `features/operations/health.ts` (D-048).
- Start-up config check runs in `instrumentation-node.ts` and **exits** on a fatal problem; a
  throwing `register()` doesn't stop Next.js (D-049). New production env vars go in `lib/env.ts`.
- Deploys are manual only (`deploy.yml`, owner-approved `production` environment). Never add an
  automatic production deploy or turn on Render auto-deploy (D-050). `MIGRATE_DATABASE_URL`
  (direct) overrides `DATABASE_URL` for the Prisma CLI.
- The service worker (`public/sw.js`) registers in production builds only. Bump `VERSION` in it
  when caching rules change. Test offline flows with `npm run build` + Playwright.
